== 일반

몇 가지 일반적인 질문과 답변이 있습니다.

.ONTAP Select Deploy와 ONTAP Select의 차이점은 무엇입니까?
ONTAP Select Deploy는 ONTAP Select 클러스터를 생성하는 데 사용되는 유틸리티입니다. 현재 ONTAP Select Deploy는 운영 클러스터를 생성하는 유일한 방법입니다. ONTAP Select Deploy를 사용하여 평가용 Select 클러스터를 생성하고, 고객이 운영 구축의 실제 단계를 테스트하고 문서화할 수도 있습니다. ONTAP Select Deploy는 평가 기간 동안 사용된 공간을 충당할 수 있는 충분한 용량의 적절한 Capacity Tier 라이센스를 사용하여 평가용 클러스터를 운영 클러스터로 전환할 수도 있습니다.

ONTAP Select Deploy는 ONTAP Select 이미지가 포함된 가상 머신입니다. 클러스터 설치 중에 ONTAP Select Deploy는 ONTAP Select 최소 요구 사항을 충족하는지 확인하기 위해 여러 가지 검사를 수행합니다. ONTAP Select Deploy VM과 Select 클러스터는 별도로 업그레이드할 수 있습니다.

.ONTAP Select의 성능 문제를 해결하려면 어떻게 해야 합니까?
FAS의 ONTAP와 마찬가지로 perfstat 유틸리티를 사용하여 성능 데이터를 수집해야 합니다. 다음은 샘플 명령입니다.

[listing]
----
perfstat8 –i N,m -t <sample time in minutes> --verbose --nodes=<filer IP> --diag-passwd=abcxyz --mode="cluster-mode" > <name of output file>
----
.ONTAP Select Deploy의 Swagger API 페이지에 어떻게 액세스합니까?
[listing]
----
http://<Deploy-IP-Address/api/ui
----

NOTE: API v3 릴리스는 이전 버전의 API와 하위 호환되지 않습니다. 새로운 API 프로시저는 https://library.netapp.com/ecm/ecm_download_file/ECMLP2845694["Field Portal"^]에서 확인할 수 있습니다.

.ONTAP Select VM을 VMware 또는 다른 타사 스냅샷으로 백업할 수 있습니까?
아니요. ONTAP Select VM은 VMware 기반 스냅샷에서 제외되는 독립형 영구 드라이브를 사용합니다. ONTAP Select를 백업하는 유일한 지원 방법은 SnapMirror 또는 SnapVault입니다.

.이 FAQ에서 다루지 않은 질문에 대한 설명은 어디에서 확인할 수 있습니까?
link:mailto:ng-ses-ontap-select@netapp.com["ng-ses-ontap-select@netapp.com"]에 문의하십시오.

== 라이센스, 설치, 업그레이드 및 되돌리기

라이선스, 설치, 업그레이드 및 되돌리기와 관련된 몇 가지 질문과 답변이 있습니다.

.ONTAP Select와 ONTAP Select Deploy는 별도로 업그레이드할 수 있습니까?
예. ONTAP Select Deploy 유틸리티는 ONTAP Select 클러스터와 별도로 업그레이드할 수 있습니다. 마찬가지로 Select 클러스터는 ONTAP Select Deploy 유틸리티와 별도로 업그레이드할 수 있습니다.

.ONTAP Select를 FAS 클러스터와 동일한 절차를 사용하여 업그레이드할 수 있습니까?
예, Select 클러스터의 업그레이드 절차는 FAS 클러스터의 업그레이드 절차와 동일합니다. 다만 ONTAP Select 업그레이드 바이너리는 FAS의 ONTAP 업그레이드 바이너리와는 별도로 다운로드해야 합니다.

.ONTAP Select를 FAS 클러스터와 동일한 절차로 되돌릴 수 있습니까?
네, ONTAP Select 클러스터의 복원 절차는 FAS 클러스터의 복원 절차와 거의 동일합니다. 하지만 몇 가지 차이점이 있습니다.

* 업그레이드된 ONTAP Select 인스턴스만 되돌릴 수 있으며, 원래 설치 버전까지만 되돌릴 수 있습니다. 새로 설치한 버전은 ONTAP Select에서 일반적으로 이전 릴리스를 지원하는 경우에도 이전 코드 릴리스로 되돌릴 수 없습니다.
* 소프트웨어 RAID를 사용하는 ONTAP Select(KVM) 및 ONTAP Select(ESXi)의 경우, 소프트웨어 RAID를 지원하지 않는 이전 버전으로 되돌릴 수 없습니다. 또한, ESXi에 ONTAP Select 9.5 이상 버전을 새로 설치하면 VMXNET3 네트워크 드라이버와 (가능한 경우) vNVMe 드라이버가 사용됩니다. 이러한 새 설치는 이전 버전의 ONTAP Select로 되돌릴 수 없습니다.
* ONTAP Select VM이 대형 인스턴스(Premium XL 라이센스 사용)로 업그레이드된 경우, 9.6 이전 버전으로 되돌리는 것은 지원되지 않습니다. 이전 버전에서는 대형 인스턴스 기능을 사용할 수 없기 때문입니다.


.ONTAP MetroCluster SDS를 사용하려면 최소한 프리미엄 라이선스가 필요합니까?
예.

.ONTAP Select 클러스터 네트워크 구성을 설치 후 변경할 수 있습니까?
다음 ONTAP Select 클러스터 속성에 대한 변경 사항은 UI, CLI 또는 REST API를 통해 사용할 수 있는 클러스터 새로 고침 작업을 사용하여 ONTAP Select Deploy에서 인식됩니다.

* 네트워크 구성(IP 주소, DNS, NTP, 넷마스크 및 게이트웨이)
* ONTAP Select 클러스터, 노드 이름 및 버전


다음과 같은 ONTAP Select VM 변경 사항도 인식됩니다.

* ONTAP Select VM 이름 및 상태 변경(예: 온라인 또는 오프라인)
* 호스트 네트워크 이름 및 스토리지 풀 이름 변경


ONTAP Select Deploy 2.6으로 업그레이드하면 이미 배포되었지만 원래 구성에서 변경되지 않은 ONTAP Select 클러스터에 대해 이러한 변경 사항을 지원할 수 있습니다. 즉, 위에서 언급한 ONTAP Select 클러스터 속성이 System Manager 또는 vCenter를 사용하여 변경된 경우 ONTAP Select Deploy 2.6으로 업그레이드해도 이러한 불일치가 해결되지 않습니다. ONTAP Select Deploy가 각 ONTAP Select VM에 고유한 메타데이터를 추가하려면 먼저 ONTAP Select 속성 변경 사항을 롤백해야 합니다.

.설치 후 ONTAP Select Deploy 네트워크 구성을 변경할 수 있습니까?
환경에서 실행 중인 Deploy 인스턴스의 네트워킹 세부 정보를 수정하는 것은 지원되지 않습니다. 자세한 내용은 기술 자료 문서 link:https://kb.netapp.com/onprem/ontap/ONTAP_Select/Modifying_DNS_configuration_of_ONTAP_Deploy_instance["ONTAP Deploy 인스턴스의 DNS 구성 수정"^]를 참조하십시오.

.Deploy는 ONTAP Select 라이센스가 갱신되었는지 어떻게 감지합니까?
방법은 모든 라이센스에 대해 동일하지만, Capacity Tier 라이센스인지 Capacity Pool 라이센스인지에 따라 세부 사항이 다릅니다.

* ONTAP Select Deploy는 NetApp에서 업데이트된 라이선스 파일을 구매하여 라이선스 및 지원 계약이 갱신되었는지 감지합니다. 라이선스 파일(.NLF)에는 용량, 시작 날짜 및 종료 날짜가 포함되며 link:https://mysupport.netapp.com/site/["NetApp 지원 사이트"^]에서 생성된 후 Deploy 서버에서 업데이트됩니다.
+

NOTE: *Add* 및 *Update* 기능을 사용하여 NLF를 Deploy 서버에 로드할 수 있습니다. *Add*는 서버에 새 라이센스를 추가하고, *Update*는 용량, 노드 라이센스(Standard, Premium, Premium XL), 지원 시작 및 종료 날짜(Capacity Tier 라이센스) 또는 구독 시작 및 종료 날짜(Capacity Pool 라이센스)와 같은 정보로 기존 파일을 업데이트합니다.

+

CAUTION: 라이센스 파일을 수정하지 마십시오. 수정 시 보안 키가 무효화되어 라이센스가 효력을 잃게 됩니다.

* *용량 등급 라이선스*는 ONTAP Select 노드 일련 번호에 연결된 노드별 영구 라이선스입니다. 이 라이선스는 별도의 지원 계약과 함께 판매됩니다. 라이선스 자체는 영구적이지만, ONTAP Select 업그레이드를 이용하고 NetApp 기술 지원의 지원을 받으려면 지원 계약을 갱신해야 합니다. 용량이나 노드 크기와 같은 라이선스 매개변수를 변경하려면 유효한 지원 계약이 필요합니다.
+
Capacity Tier 라이센스 업데이트, 파라미터 변경 또는 지원 계약 갱신을 구매하려면 주문 시 노드 일련 번호가 필요합니다. Capacity Tier 노드 일련 번호는 9자리 숫자이며 '32'로 시작합니다.

+
구매가 완료되고 라이센스 파일이 생성되면 *Update* 기능을 사용하여 Deploy 서버에 업로드됩니다.

* *Capacity Pool 라이센스*는 특정 용량 풀과 노드 크기(standard, premium, premium XL)를 사용하여 하나 이상의 클러스터를 구축할 수 있는 권한에 대한 서브스크립션입니다. 서브스크립션에는 지정된 기간 동안 라이센스 및 지원을 사용할 수 있는 권한이 포함됩니다. 라이센스 사용 권한과 지원 계약에는 시작 날짜와 종료 날짜가 지정되어 있습니다.


.Deploy는 노드에 라이센스 또는 지원 계약이 갱신되었는지 어떻게 감지합니까?
업데이트된 라이선스 파일을 구매, 생성 및 업로드하는 것은 Deploy가 갱신된 라이선스 및 지원 계약을 감지하는 방법입니다.

용량 등급 지원 계약 만료일이 지난 경우 노드는 계속 실행될 수 있지만, 지원 계약을 먼저 최신 상태로 유지하지 않으면 ONTAP 업데이트를 다운로드 및 설치하거나 NetApp 기술 지원팀에 문의하여 지원을 받을 수 없습니다.

Capacity Pool 구독이 만료되면 시스템에서 먼저 경고를 표시하지만, 30일 후 시스템이 종료되면 Deploy 서버에 업데이트된 구독이 설치될 때까지 재부팅되지 않습니다.

== 스토리지

스토리지와 관련된 몇 가지 질문과 답변이 있습니다.

.단일 ONTAP Select Deploy 인스턴스로 ESXi와 KVM 모두에서 클러스터를 생성할 수 있습니까?
예. ONTAP Select Deploy는 KVM 또는 ESXi에 설치할 수 있으며, 두 설치 환경 모두에서 두 하이퍼바이저 중 하나에 ONTAP Select 클러스터를 생성할 수 있습니다.

.ESXi에서 ONTAP Select를 사용하려면 vCenter가 필수인가요?
ESXi 호스트가 적절하게 라이선스가 부여된 경우, ESXi 호스트가 vCenter Server에 의해 관리될 필요는 없습니다. 그러나 호스트가 vCenter server에 의해 관리되는 경우, ONTAP Select Deploy를 해당 vCenter Server를 사용하도록 구성해야 합니다. 즉, ESXi 호스트가 vCenter Server에 의해 적극적으로 관리되고 있다면 ONTAP Select Deploy에서 독립형으로 ESXi 호스트를 구성할 수 없습니다. ONTAP Select Deploy VM은 vMotion 또는 VMware HA 이벤트로 인해 ESXi 호스트 간에 발생하는 모든 ONTAP Select VM 마이그레이션을 추적하기 위해 vCenter에 의존한다는 점에 유의하십시오.

.소프트웨어 RAID란 무엇입니까?
ONTAP Select는 하드웨어 RAID 컨트롤러가 없는 서버를 사용할 수 있습니다. 이 경우 RAID 기능은 소프트웨어로 구현됩니다. 소프트웨어 RAID를 사용할 때는 SSD와 NVMe 드라이브가 모두 지원됩니다. ONTAP Select 부팅 및 코어 디스크는 가상화된 파티션(스토리지 풀 또는 데이터 저장소) 내에 있어야 합니다. ONTAP Select는 RD2(루트-데이터-데이터 파티셔닝)를 사용하여 SSD를 파티셔닝합니다. 따라서 ONTAP Select 루트 파티션은 데이터 애그리게이트에 사용되는 것과 동일한 물리적 스핀들에 위치합니다. 하지만 루트 애그리게이트와 부팅 및 코어 가상화 디스크는 용량 라이센스에 포함되지 않습니다.

AFF/FAS에서 사용 가능한 모든 RAID 방법은 ONTAP Select에서도 사용할 수 있습니다. 여기에는 RAID 4, RAID DP 및 RAID-TEC가 포함됩니다. 최소 SSD 개수는 선택한 RAID 구성 유형에 따라 다릅니다. 모범 사례에서는 최소 하나 이상의 스페어가 있어야 합니다. 스페어 및 패리티 디스크는 용량 라이센스에 포함되지 않습니다.

.소프트웨어 RAID는 하드웨어 RAID 구성과 어떻게 다릅니까?
소프트웨어 RAID는 ONTAP 소프트웨어 스택의 한 계층입니다. 소프트웨어 RAID는 물리적 드라이브가 파티션되어 ONTAP Select VM 내에서 원시 디스크로 사용 가능하므로 관리 제어 기능을 강화합니다. 반면 하드웨어 RAID는 일반적으로 하나의 큰 LUN을 제공하며, 이 LUN을 분할하여 ONTAP Select에서 볼 수 있는 VMDISK를 생성할 수 있습니다. 소프트웨어 RAID는 옵션으로 제공되며 하드웨어 RAID 대신 사용할 수 있습니다.

소프트웨어 RAID의 일부 요구 사항은 다음과 같습니다.

* ESXi 및 KVM에서 지원됩니다
+
** ONTAP Select 9.14.1부터 KVM 하이퍼바이저에 대한 지원이 복원되었습니다. 이전에는 ONTAP Select 9.10.1에서 KVM 하이퍼바이저에 대한 지원이 제거되었습니다.


* 지원되는 물리적 디스크 크기: 200GB – 32TB
* DAS 구성에서만 지원됩니다.
* SSD 또는 NVMe에서 지원됩니다
* Premium 또는 Premium XL ONTAP Select 라이센스가 필요합니다
* 하드웨어 RAID 컨트롤러가 없거나 비활성화되어 있거나, 또는 SAS HBA 모드로 작동해야 합니다
* 시스템 디스크(코어 덤프, 부트/NVRAM 및 Mediator)에는 전용 LUN 기반의 LVM 스토리지 풀 또는 데이터 저장소를 사용해야 합니다.


.ONTAP Select for KVM은 여러 개의 NIC 본드를 지원합니까?
KVM에 설치할 때는 하나의 본드와 하나의 브리지를 사용해야 합니다. 물리적 포트가 두 개 또는 네 개인 호스트는 모든 포트를 동일한 본드에 연결해야 합니다.

.ONTAP Select는 하이퍼바이저 호스트의 물리적 디스크 또는 NIC 장애를 어떻게 보고하거나 경고합니까? ONTAP Select는 하이퍼바이저에서 이 정보를 검색합니까, 아니면 하이퍼바이저 수준에서 모니터링을 설정해야 합니까?
하드웨어 RAID 컨트롤러를 사용하는 경우 ONTAP Select는 기본 서버 문제를 대부분 인식하지 못합니다. 서버가 권장 사례에 따라 구성되어 있다면 일정 수준의 이중화가 존재해야 합니다. 드라이브 장애를 견디려면 RAID 5/6을 권장합니다. 소프트웨어 RAID 구성의 경우 ONTAP는 디스크 장애에 대한 알림을 발행하고 예비 드라이브가 있는 경우 드라이브 재구축을 시작합니다.

네트워크 계층에서 단일 장애 지점을 방지하려면 최소 두 개의 물리적 NIC를 사용해야 합니다. NetApp에서는 데이터, 관리 및 내부 포트 그룹에 팀 또는 본드에 두 개 이상의 업링크를 사용하여 NIC 팀 구성 및 본딩을 구성할 것을 권장합니다. 이러한 구성을 통해 업링크 장애가 발생할 경우 가상 스위치가 장애가 발생한 업링크의 트래픽을 NIC 팀 내의 정상 업링크로 이동시킬 수 있습니다. 권장 네트워크 구성에 대한 자세한 내용은 link:reference_plan_best_practices.html#networking["모범 사례 요약: 네트워킹"]을 참조하십시오.

2노드 또는 4노드 클러스터의 경우, 다른 모든 오류는 ONTAP HA에서 처리합니다. 하이퍼바이저 서버를 교체하고 새 서버로 ONTAP Select 클러스터를 재구성해야 하는 경우, _ONTAP Select 노드를 복구할 수 있습니까?_를 참조하십시오.

.ONTAP Select 노드를 복구할 수 있습니까?
ONTAP Select VM 또는 호스트가 완전히 손실되었거나 단일 노드 클러스터가 실수로 삭제된 경우와 같이 ONTAP Select 노드를 복구해야 하는 경우 NetApp 기술 지원팀에 문의하십시오. 자세한 내용은 기술 자료 문서 link:https://kb.netapp.com/on-prem/ontap/ontap-select/Select-KBs/ONTAP_Select_node_VM_recovery_in_case_of_disaster["재해 발생 시 ONTAP Select 노드 VM 복구"^]를 참조하십시오.

.ONTAP Select에서 지원하는 최대 데이터 저장소 크기는 얼마입니까?
vSAN을 포함한 모든 구성은 ONTAP Select 노드당 400TB의 스토리지를 지원합니다.

지원되는 최대 크기보다 큰 데이터 저장소에 설치할 경우 제품 설정 중에 Capacity Cap을 사용해야 합니다.

.ONTAP Select 노드의 용량을 늘리는 방법은 무엇입니까?
ONTAP Select Deploy에는 ONTAP Select 노드의 용량 확장 작업을 지원하는 스토리지 추가 워크플로가 포함되어 있습니다. 동일한 데이터스토어의 공간(사용 가능한 공간이 있는 경우)을 사용하거나 별도의 데이터스토어에서 공간을 추가하여 관리 중인 스토리지를 확장할 수 있습니다. 동일한 애그리게이트에서 로컬 데이터스토어와 원격 데이터스토어를 혼합하여 사용하는 것은 지원되지 않습니다.

스토리지 추가 기능은 소프트웨어 RAID도 지원합니다. 단, 소프트웨어 RAID를 사용하려면 ONTAP Select VM에 추가 물리적 드라이브를 추가해야 합니다. 이 경우 스토리지 추가는 FAS 또는 AFF 어레이 관리와 유사합니다. 소프트웨어 RAID를 사용하여 ONTAP Select 노드에 스토리지를 추가할 때는 RAID 그룹 크기와 드라이브 크기를 고려해야 합니다.

.ONTAP Select는 vSAN 또는 외부 어레이 유형 데이터스토어를 지원합니까?
ONTAP Select Deploy 및 ONTAP Select for ESXi는 스토리지 풀에 vSAN 또는 외부 어레이 유형의 데이터 저장소를 사용하는 ONTAP Select 단일 노드 클러스터 구성을 지원합니다.

ONTAP Select Deploy 및 ONTAP Select for KVM은 외부 어레이에서 공유 논리 스토리지 풀 유형을 사용하여 ONTAP Select 단일 노드 클러스터 구성을 지원합니다. 스토리지 풀은 iSCSI 또는 FC/FCoE 기반일 수 있습니다. 다른 유형의 스토리지 풀은 지원되지 않습니다.

공유 스토리지의 다중 노드 HA 클러스터가 지원됩니다.

.ONTAP Select는 vSAN 또는 일부 HCI 스택을 포함한 기타 공유 외부 스토리지에서 다중 노드 클러스터를 지원합니까?
외부 스토리지(다중 노드 vNAS)를 사용하는 다중 노드 클러스터는 ESXi와 KVM 모두에서 지원됩니다. 동일 클러스터 내에서 여러 하이퍼바이저를 혼합하여 사용하는 것은 지원되지 않습니다. 공유 스토리지의 HA 아키텍처는 여전히 HA 쌍의 각 노드가 파트너 데이터의 미러 복사본을 가지고 있음을 의미합니다. 그러나 다중 노드 클러스터는 VMware HA 또는 KVM Live Motion에 의존하는 단일 노드 클러스터와 달리 ONTAP 무중단 운영의 이점을 제공합니다.

ONTAP Select Deploy는 동일 호스트에 여러 ONTAP Select VM을 지원하지만, 클러스터 생성 시 이러한 인스턴스가 동일한 ONTAP Select 클러스터에 포함되는 것은 허용하지 않습니다. ESXi 환경의 경우, NetApp은 VMware HA가 동일한 ONTAP Select 클러스터에 속한 여러 ONTAP Select VM을 단일 ESXi 호스트로 마이그레이션하지 않도록 VM 안티 어피니티 규칙을 생성하는 것을 권장합니다. 또한, ONTAP Select Deploy는 관리자(사용자)가 시작한 vMotion 또는 라이브 마이그레이션으로 인해 두 개의 ONTAP Select 노드가 동일한 물리적 호스트에 위치하는 등 모범 사례를 위반한 경우, ONTAP Select Deploy UI와 로그에 경고를 표시합니다. ONTAP Select Deploy가 ONTAP Select VM의 위치를 파악하는 유일한 방법은 클러스터 새로 고침 작업이며, 이는 ONTAP Select Deploy 관리자가 시작해야 하는 수동 작업입니다. ONTAP Select Deploy에는 사전 예방적 모니터링을 지원하는 기능이 없으며, 경고는 Deploy UI 또는 로그를 통해서만 확인할 수 있습니다. 즉, 이 경고는 중앙 집중식 모니터링 인프라로 전달될 수 없습니다.

.ONTAP Select는 VMware NSX VXLAN을 지원합니까?
NSX-V VXLAN 포트 그룹이 지원됩니다. ONTAP MetroCluster SDS를 포함한 다중 노드 HA의 경우 VXLAN 오버헤드를 수용하기 위해 내부 네트워크 MTU를 7500에서 8900 사이(9000 대신)로 구성해야 합니다. 내부 네트워크 MTU는 클러스터 배포 중에 ONTAP Select Deploy를 사용하여 구성할 수 있습니다.

.ONTAP Select는 KVM 라이브 마이그레이션을 지원합니까?
외부 어레이 스토리지 풀에서 실행되는 ONTAP Select VM은 virsh 라이브 마이그레이션을 지원합니다.

.vSAN AF에 ONTAP Select Premium이 필요합니까?
아니요, 외부 어레이 또는 vSAN 구성이 모두 플래시인지 여부와 관계없이 모든 버전이 지원됩니다.

.어떤 vSAN FTT/FTM 설정이 지원됩니까?
Select VM은 vSAN 데이터 저장소 스토리지 정책을 상속하며 FTT/FTM 설정에 대한 제한이 없습니다. 그러나 FTT/FTM 설정에 따라 ONTAP Select VM 크기가 설정 중에 구성된 용량보다 훨씬 클 수 있습니다. ONTAP Select는 설정 중에 생성되는 thick-eager, zeroed VMDK를 사용합니다. 동일한 공유 데이터 저장소를 사용하는 다른 VM에 영향을 주지 않으려면 Select 용량 및 FTT/FTM 설정에서 파생된 실제 Select VM 크기를 수용할 수 있도록 데이터 저장소에 충분한 여유 용량을 제공하는 것이 중요합니다.

.서로 다른 Select 클러스터에 속한 ONTAP Select 노드 여러 개가 동일한 호스트에서 실행될 수 있습니까?
ONTAP Select vNAS 구성의 경우, 동일한 호스트에 여러 ONTAP Select 노드를 구성할 수 있지만, 이러한 노드들이 동일한 ONTAP Select 클러스터에 속해서는 안 됩니다. DAS 구성에서는 동일한 물리적 호스트에 여러 ONTAP Select 노드가 존재할 경우 RAID 컨트롤러에 대한 접근 권한을 두고 경쟁하게 되므로 이러한 구성은 지원되지 않습니다.

.단일 10GE 포트를 가진 호스트에서 ONTAP Select를 실행할 수 있으며, ESXi와 KVM 모두에서 사용할 수 있습니까?
10GE 포트 하나를 사용하여 외부 네트워크에 연결할 수 있습니다. 하지만 NetApp은 공간이 제한된 소형 폼팩터 환경에서만 이 구성을 사용할 것을 권장합니다. 이 기능은 ESXi와 KVM 모두에서 지원됩니다.

.KVM에서 라이브 마이그레이션을 수행하려면 어떤 추가 프로세스를 실행해야 합니까?
라이브 마이그레이션에 참여하는 각 호스트에 오픈 소스 CLVM 및 pacemaker (pcs) 구성 요소를 설치하고 실행해야 합니다. 이는 각 호스트에서 동일한 볼륨 그룹에 액세스하는 데 필요합니다.



[[vcenter]]
== vCenter

VMware vCenter와 관련된 몇 가지 질문과 답변이 있습니다.

.ONTAP Select Deploy는 vCenter와 어떻게 통신하며 어떤 방화벽 포트를 열어야 합니까?
ONTAP Select Deploy는 VMware VIX API를 사용하여 vCenter, ESXi 호스트 또는 둘 다와 통신합니다. VMware 설명서에 따르면 vCenter Server 또는 ESXi 호스트에 대한 초기 연결은 TCP 포트 443에서 HTTPS/SOAP를 사용하여 수행됩니다. 이 포트는 TLS/SSL을 통한 보안 HTTP에 사용됩니다. 두 번째로, ESXi 호스트와의 연결은 TCP 포트 902의 소켓을 통해 이루어집니다. 이 연결을 통해 전송되는 데이터는 SSL로 암호화됩니다. 또한 ONTAP Select Deploy는  `PING` 명령을 실행하여 사용자가 지정한 IP 주소에서 응답하는 ESXi 호스트가 있는지 확인합니다.

ONTAP Select Deploy는 다음과 같이 ONTAP Select 노드 및 클러스터 관리 IP 주소와 통신할 수 있어야 합니다.

* 핑
* SSH(포트 22)
* SSL(포트 443)


2노드 클러스터의 경우 ONTAP Select Deploy가 클러스터 사서함을 호스팅합니다. 각 ONTAP Select 노드는 iSCSI(포트 3260)를 통해 ONTAP Select Deploy에 연결할 수 있어야 합니다.

다중 노드 클러스터의 경우 내부 네트워크가 완전히 개방되어 있어야 합니다(NAT 또는 방화벽 없음).

.ONTAP Select Deploy가 ONTAP Select 클러스터를 생성하려면 어떤 vCenter 권한이 필요합니까?
필요한 vCenter 권한 목록은 여기에서 확인할 수 있습니다. link:reference_plan_ots_vcenter.html["VMware vCenter 서버"]



[[ha-and-clusters]]
== HA 및 클러스터

HA 쌍 및 클러스터와 관련된 몇 가지 질문과 답변이 있습니다.

.4노드, 6노드 또는 8노드 클러스터와 2노드 ONTAP Select 클러스터의 차이점은 무엇입니까?
4노드, 6노드 및 8노드 클러스터에서는 ONTAP Select Deploy VM이 주로 클러스터 생성에 사용되는 반면, 2노드 클러스터는 HA 쿼럼을 위해 ONTAP Select Deploy VM에 지속적으로 의존합니다. ONTAP Select Deploy VM을 사용할 수 없는 경우 페일오버 서비스가 비활성화됩니다.

.MetroCluster SDS란 무엇인가요?
MetroCluster SDS는 NetApp의 MetroCluster Business Continuity 솔루션 범주에 속하는 저비용 동기식 복제 옵션입니다. 이 옵션은 ONTAP Select에서만 사용할 수 있으며, FAS Hybrid Flash, AFF, NetApp Private Storage for Cloud에서 사용할 수 있는 NetApp MetroCluster와는 다릅니다.

.MetroCluster SDS는 NetApp MetroCluster와 어떻게 다릅니까?
MetroCluster SDS는 동기식 복제 솔루션을 제공하며 NetApp MetroCluster 솔루션 제품군에 속합니다. 하지만 연결 유형이 다르다는 점이 주요 차이점입니다(FC 및 IP가 아닌 IP 네트워크만 지원).

.2노드 ONTAP Select 클러스터와 2노드 ONTAP MetroCluster SDS의 차이점은 무엇입니까?
2노드 클러스터는 두 노드가 동일한 데이터 센터 내에 있고 서로 300m 이내에 위치한 클러스터로 정의됩니다. 일반적으로 두 노드는 동일한 네트워크 스위치 또는 Inter-Switch Link로 연결된 네트워크 스위치 세트에 대한 업링크를 갖습니다.

2노드 MetroCluster SDS는 물리적으로 분리된(다른 방, 다른 건물 또는 다른 데이터 센터) 노드가 있는 클러스터로 정의되며 각 노드의 업링크 연결은 별도의 네트워크 스위치에 연결됩니다. MetroCluster SDS는 전용 하드웨어가 필요하지 않지만 환경은 최소 지연 시간 요구 사항(RTT 5ms 및 지터 5ms, 총 최대 10ms)을 지원해야 합니다.

MetroCluster SDS는 프리미엄 기능으로, Premium 또는 Premium XL 라이선스가 필요합니다. Premium 라이선스는 소형 및 중형 VM 생성은 물론 HDD 및 SSD 미디어 생성도 지원합니다. 이러한 모든 구성이 지원됩니다.

.ONTAP MetroCluster SDS는 로컬 스토리지(DAS)가 필요합니까?
ONTAP MetroCluster SDS는 모든 유형의 스토리지 구성(DAS 및 vNAS)을 지원합니다.

.ONTAP MetroCluster SDS는 소프트웨어 RAID를 지원합니까?
예, 소프트웨어 RAID는 KVM과 ESXi 모두에서 SSD 미디어로 지원됩니다.

.ONTAP MetroCluster SDS는 SSD와 회전식 저장장치를 모두 지원합니까?
네, Premium 라이센스가 필요하지만 이 라이센스는 소형 및 중형 VM과 SSD 및 스피닝 미디어를 모두 지원합니다.

.ONTAP MetroCluster SDS는 4노드 이상의 클러스터 크기를 지원합니까?
아니요, Mediator가 있는 2노드 클러스터만 MetroCluster SDS로 구성할 수 있습니다.

.ONTAP MetroCluster SDS의 요구 사항은 무엇입니까?
요구 사항은 다음과 같습니다.

* 데이터 센터 3곳(ONTAP Select Deploy Mediator용 1곳과 각 노드용 1곳)
* RTT 5ms 및 지터 5ms로 최대 총 10ms
* ONTAP Select Deploy Mediator와 각 ONTAP Select 노드 간의 RTT는 125ms, 최소 대역폭은 5Mbps입니다
* Premium 또는 Premium XL 라이센스


.ONTAP Select는 vMotion 또는 VMware HA를 지원합니까?
vSAN 데이터스토어 또는 외부 어레이 데이터스토어(즉, vNAS 배포)에서 실행되는 ONTAP Select VM은 vMotion, DRS 및 VMware HA 기능을 지원합니다.

.ONTAP Select는 Storage vMotion을 지원합니까?
Storage vMotion은 단일 노드 및 다중 노드 ONTAP Select 클러스터와 ONTAP Select Deploy VM을 포함한 모든 구성에서 지원됩니다. Storage vMotion을 사용하여 ONTAP Select 또는 ONTAP Select Deploy VM을 서로 다른 VMFS 버전(예: VMFS 5에서 VMFS 6) 간에 마이그레이션할 수 있지만 이 사용 사례로만 제한되지는 않습니다. Storage vMotion 작업을 시작하기 전에 VM을 종료하는 것이 좋습니다. 스토리지 vMotion 작업이 완료된 후 ONTAP Select Deploy는 다음 작업을 실행해야 합니다.

[listing]
----
cluster refresh
----

NOTE: 서로 다른 유형의 데이터스토어 간 스토리지 vMotion 작업은 지원되지 않습니다. 즉, NFS 유형 데이터스토어와 VMFS 데이터스토어 간의 스토리지 vMotion 작업은 지원되지 않습니다. 일반적으로 외부 데이터스토어와 DAS 데이터스토어 간의 스토리지 vMotion 작업은 지원되지 않습니다.

.ONTAP Select 노드 간의 HA 트래픽을 다른 vSwitch 및/또는 분리된 물리적 포트를 통해 또는 ESXi 호스트 간에 지점 간 IP 케이블을 사용하여 실행할 수 있습니까?
이러한 구성은 지원되지 않습니다. ONTAP Select는 클라이언트 트래픽을 전달하는 물리적 네트워크 업링크의 상태를 확인할 수 없습니다. 따라서 ONTAP Select는 HA 하트비트를 사용하여 VM이 클라이언트와 피어 모두에게 동시에 액세스 가능한지 확인합니다. 물리적 연결이 끊어지면 HA 하트비트가 손실되어 다른 노드로 자동 페일오버가 발생하며, 이는 바람직한 동작입니다.

HA 트래픽을 별도의 물리적 인프라에 분리하면 Select VM이 피어와는 통신할 수 있지만 클라이언트와는 통신할 수 없는 상황이 발생할 수 있습니다. 이로 인해 자동 HA 프로세스가 중단되고 수동 페일오버가 실행될 때까지 데이터에 액세스할 수 없게 됩니다.

== 중재자 서비스

중재자 서비스를 다루는 몇 가지 질문과 답변이 있습니다.

.Mediator 서비스란 무엇입니까?
2노드 클러스터는 HA 쿼럼을 위해 ONTAP Select Deploy VM에 지속적으로 의존합니다. 2노드 HA 쿼럼 협상에 참여하는 ONTAP Select Deploy VM을 미디에이터 VM이라고 합니다.

.Mediator 서비스를 원격으로 사용할 수 있습니까?
예. 2노드 HA 쌍의 중재자 역할을 하는 ONTAP Select Deploy는 최대 500ms RTT의 WAN 지연 시간을 지원하며 최소 5Mbps의 대역폭이 필요합니다.

.Mediator 서비스는 어떤 프로토콜을 사용합니까?
Mediator 트래픽은 iSCSI이며, ONTAP Select 노드 관리 IP 주소에서 시작되어 ONTAP Select Deploy IP 주소에서 종료됩니다. 2노드 클러스터를 사용할 때는 ONTAP Select 노드 관리 IP 주소에 IPv6를 사용할 수 없습니다.

.하나의 Mediator 서비스를 여러 개의 2노드 HA 클러스터에 사용할 수 있습니까?
예. 각 ONTAP Select Deploy VM은 최대 100개의 2노드 ONTAP Select 클러스터에 대한 공통 Mediator 서비스 역할을 할 수 있습니다.

.배포 후 Mediator 서비스 위치를 변경할 수 있습니까?
예. 다른 ONTAP Select Deploy VM을 사용하여 Mediator 서비스를 호스팅할 수 있습니다.

.ONTAP Select는 Mediator를 사용하거나 사용하지 않고 확장 클러스터를 지원합니까?
확장형 HA 배포 모델에서는 Mediator가 포함된 2노드 클러스터만 지원됩니다.
