[role="lead"]
ONTAP Select는 단일 노드 및 다중 노드 네트워크 구성을 모두 지원합니다.



[[single-node-network-configuration]]
== 단일 노드 네트워크 구성

단일 노드 ONTAP Select 구성은 클러스터, HA 또는 미러 트래픽이 없으므로 ONTAP 내부 네트워크가 필요하지 않습니다.

ONTAP Select 제품의 다중 노드 버전과 달리 각 ONTAP Select VM에는 ONTAP 네트워크 포트 e0a, e0b 및 e0c에 제공되는 3개의 가상 네트워크 어댑터가 포함되어 있습니다.

이러한 포트는 관리, 데이터 및 인터클러스터 LIF를 제공하는 데 사용됩니다.

.KVM
ONTAP Select를 단일 노드 클러스터로 배포할 수 있습니다. 하이퍼바이저 호스트에는 외부 네트워크에 대한 액세스를 제공하는 가상 스위치가 포함되어 있습니다.

.ESXi
다음 그림은 이러한 포트와 기본 물리적 어댑터 간의 관계를 보여줍니다. 이 그림은 ESXi 하이퍼바이저의 ONTAP Select 클러스터 노드 하나를 나타냅니다.

*단일 노드 ONTAP Select 클러스터의 네트워크 구성*

image:DDN_03.jpg["단일 노드 ONTAP Select 클러스터의 네트워크 구성"]


NOTE: 단일 노드 클러스터에는 2개의 어댑터만 있으면 충분하지만 NIC 팀 구성은 여전히 필요합니다.



[[lif-assignment]]
=== LIF 할당

이 문서의 다중 노드 LIF 할당 섹션에서 설명했듯이 ONTAP는 클러스터 네트워크 트래픽을 데이터 및 관리 트래픽과 분리하기 위해 IPspace를 사용합니다. 이 플랫폼의 단일 노드 버전에는 클러스터 네트워크가 포함되어 있지 않습니다. 따라서 클러스터 IPspace에 포트가 없습니다.


NOTE: ONTAP Select 클러스터 설정 중에 클러스터 및 노드 관리 LIF가 자동으로 생성됩니다. 나머지 LIF는 배포 후에 생성할 수 있습니다.



[[management-and-data-lifs-e0a-e0b-and-e0c]]
=== 관리 및 데이터 LIF(e0a, e0b 및 e0c)

ONTAP 포트 e0a, e0b 및 e0c는 다음과 같은 유형의 트래픽을 전송하는 LIF의 후보 포트로 지정됩니다.

* SAN/NAS 프로토콜 트래픽(CIFS, NFS 및 iSCSI)
* 클러스터, 노드 및 SVM 관리 트래픽
* 클러스터 간 트래픽(SnapMirror 및 SnapVault)




[[multi-node-network-configuration]]
== 다중 노드 네트워크 구성

다중 노드 ONTAP Select 네트워크 구성은 두 개의 네트워크로 구성됩니다.

이는 클러스터 및 내부 복제 서비스를 제공하는 내부 네트워크와 데이터 액세스 및 관리 서비스를 제공하는 외부 네트워크입니다. 이 두 네트워크 내에서 흐르는 트래픽의 엔드 투 엔드 격리는 클러스터 복원력에 적합한 환경을 구축하는 데 매우 중요합니다.

다음 그림은 VMware vSphere 플랫폼에서 실행되는 4노드 ONTAP Select 클러스터를 보여주며, 이러한 네트워크를 나타냅니다. 6노드, 8노드, 10노드 및 12노드 클러스터도 유사한 네트워크 레이아웃을 갖습니다.


NOTE: 각 ONTAP Select 인스턴스는 별도의 물리적 서버에 상주합니다. 내부 및 외부 트래픽은 별도의 네트워크 포트 그룹을 사용하여 격리되며, 이러한 포트 그룹은 각 가상 네트워크 인터페이스에 할당되어 클러스터 노드가 동일한 물리적 스위치 인프라를 공유할 수 있도록 합니다.

*ONTAP Select 다중 노드 클러스터 네트워크 구성 개요*

image:DDN_01.jpg["ONTAP Select 다중 노드 클러스터 네트워크 구성 개요"]

각 ONTAP Select VM에는 ONTAP에 e0a부터 e0g까지 7개의 네트워크 포트 세트로 제공되는 7개의 가상 네트워크 어댑터가 포함되어 있습니다. ONTAP은 이러한 어댑터를 물리적 NIC로 처리하지만, 실제로는 가상 어댑터이며 가상화된 네트워크 계층을 통해 물리적 인터페이스 세트에 매핑됩니다. 따라서 각 호스팅 서버에는 6개의 물리적 네트워크 포트가 필요하지 않습니다.


NOTE: ONTAP Select VM에 가상 네트워크 어댑터를 추가하는 것은 지원되지 않습니다.

이 포트들은 다음과 같은 서비스를 제공하도록 사전 구성되어 있습니다.

* e0a, e0b, e0g. 관리 및 데이터 LIF
* e0c, e0d. 클러스터 네트워크 LIF
* e0e. RSM
* e0f. HA 인터커넥트


포트 e0a, e0b 및 e0g는 외부 네트워크에 있습니다. 포트 e0c~e0f는 여러 가지 기능을 수행하지만 전체적으로 내부 Select 네트워크를 구성합니다. 네트워크 설계를 결정할 때 이러한 포트를 단일 계층 2 네트워크에 배치해야 합니다. 이러한 가상 어댑터를 서로 다른 네트워크에 분산할 필요가 없습니다.

이러한 포트와 기본 물리적 어댑터 간의 관계는 다음 그림에 나와 있으며, 이 그림은 ESXi 하이퍼바이저의 ONTAP Select 클러스터 노드 하나를 나타냅니다.

*다중 노드 ONTAP Select 클러스터의 일부인 단일 노드의 네트워크 구성* image:DDN_02.jpg["다중 노드 ONTAP Select 클러스터의 일부인 단일 노드의 네트워크 구성"]

내부 트래픽과 외부 트래픽을 서로 다른 물리적 NIC로 분리하면 네트워크 리소스에 대한 불충분한 액세스를 방지하여 시스템 지연을 줄일 수 있습니다. 또한 NIC 팀 구성을 통한 집계는 단일 네트워크 어댑터에 장애가 발생하더라도 ONTAP Select 클러스터 노드가 네트워크에 계속 액세스할 수 있도록 합니다.


NOTE: 외부 네트워크 포트 그룹과 내부 네트워크 포트 그룹 모두에 4개의 NIC 어댑터가 대칭적으로 포함되어 있습니다. 외부 네트워크 포트 그룹의 활성 포트는 내부 네트워크에서 대기 포트가 되고, 반대로 내부 네트워크 포트 그룹의 활성 포트는 외부 네트워크 포트 그룹에서 대기 포트가 됩니다.



[[lif-assignment]]
=== LIF 할당

IPspace가 도입되면서 ONTAP 포트 역할은 더 이상 사용되지 않습니다. FAS 어레이와 마찬가지로 ONTAP Select 클러스터에는 기본 IPspace와 클러스터 IPspace가 모두 포함됩니다. 네트워크 포트 e0a, e0b, e0g를 기본 IPspace에, 포트 e0c와 e0d를 클러스터 IPspace에 배치함으로써 해당 포트는 속하지 않는 LIF 호스팅으로부터 본질적으로 차단되었습니다. ONTAP Select 클러스터 내의 나머지 포트는 내부 서비스를 제공하는 인터페이스의 자동 할당을 통해 사용됩니다. RSM 및 HA 인터커넥트 인터페이스의 경우와 마찬가지로 ONTAP 셸을 통해 노출되지 않습니다.


NOTE: 모든 LIF가 ONTAP 명령 셸을 통해 보이는 것은 아닙니다. HA 인터커넥트 및 RSM 인터페이스는 ONTAP에서 숨겨져 있으며 각각의 서비스를 제공하기 위해 내부적으로 사용됩니다.

네트워크 포트 및 LIF에 대한 자세한 내용은 다음 섹션에 설명되어 있습니다.



[[management-and-data-lifs-e0a-e0b-and-e0g]]
=== 관리 및 데이터 LIF(e0a, e0b 및 e0g)

ONTAP 포트 e0a, e0b 및 e0g는 다음과 같은 유형의 트래픽을 전송하는 LIF의 후보 포트로 지정됩니다.

* SAN/NAS 프로토콜 트래픽(CIFS, NFS 및 iSCSI)
* 클러스터, 노드 및 SVM 관리 트래픽
* 클러스터 간 트래픽(SnapMirror 및 SnapVault)



NOTE: ONTAP Select 클러스터 설정 중에 클러스터 및 노드 관리 LIF가 자동으로 생성됩니다. 나머지 LIF는 배포 후에 생성할 수 있습니다.



[[cluster-network-lifs-e0c-e0d]]
=== 클러스터 네트워크 LIF(e0c, e0d)

ONTAP 포트 e0c와 e0d는 클러스터 인터페이스의 홈 포트로 지정됩니다. 각 ONTAP Select 클러스터 노드 내에서 ONTAP 설정 중에 링크 로컬 IP 주소(169.254.x.x)를 사용하여 두 개의 클러스터 인터페이스가 자동으로 생성됩니다.


NOTE: 이러한 인터페이스에는 고정 IP 주소를 할당할 수 없으며, 추가 클러스터 인터페이스를 생성해서도 안 됩니다.

클러스터 네트워크 트래픽은 지연 시간이 짧고 라우팅되지 않는 레이어 2 네트워크를 통해 전송되어야 합니다. 클러스터 처리량 및 지연 시간 요구 사항으로 인해 ONTAP Select 클러스터는 물리적으로 가까운 위치(예: 멀티팩, 단일 데이터 센터)에 배치해야 합니다. WAN 또는 상당한 지리적 거리에 걸쳐 HA 노드를 분리하여 4개, 6개, 8개, 10개 또는 12개 노드로 구성된 확장 클러스터 구성은 지원되지 않습니다. 중재자를 사용하는 2노드 확장 구성은 지원됩니다.

자세한 내용은 해당 섹션을 참조하십시오link:reference_plan_best_practices.html#two-node-stretched-ha-metrocluster-sds-best-practices["2노드 확장형 고가용성(MetroCluster SDS) 모범 사례"].


NOTE: 클러스터 네트워크 트래픽의 최대 처리량을 보장하기 위해 이 네트워크 포트는 점보 프레임(7500~9000 MTU)을 사용하도록 구성되어 있습니다. 클러스터가 올바르게 작동하려면 ONTAP Select 클러스터 노드에 내부 네트워크 서비스를 제공하는 모든 상위 가상 및 물리적 스위치에서 점보 프레임이 활성화되어 있는지 확인하십시오.



[[raid-syncmirror-traffic-e0e]]
=== RAID SyncMirror 트래픽(e0e)

HA 파트너 노드 간의 블록 동기 복제는 네트워크 포트 e0e에 있는 내부 네트워크 인터페이스를 사용하여 수행됩니다. 이 기능은 클러스터 설정 중에 ONTAP에서 구성한 네트워크 인터페이스를 사용하여 자동으로 수행되므로 관리자가 구성할 필요가 없습니다.


NOTE: 포트 e0e는 ONTAP 내부 복제 트래픽을 위해 예약되어 있습니다. 따라서 해당 포트와 호스팅된 LIF는 ONTAP CLI 또는 System Manager에서 볼 수 없습니다. 이 인터페이스는 자동으로 생성된 링크 로컬 IP 주소를 사용하도록 구성되어 있으며, 다른 IP 주소를 할당할 수 없습니다. 이 네트워크 포트는 점보 프레임(7500~9000 MTU)을 사용해야 합니다.



[[ha-interconnect-e0f]]
=== HA 인터커넥트(e0f)

NetApp FAS 어레이는 ONTAP 클러스터 내 HA 쌍 간 정보 전달을 위해 특수 하드웨어를 사용합니다. 하지만 소프트웨어 정의 환경에서는 InfiniBand나 iWARP 장치와 같은 이러한 유형의 장비를 사용할 수 없는 경우가 많으므로 대체 솔루션이 필요합니다. 여러 가지 가능성을 검토했지만, ONTAP의 상호 연결 전송 요구 사항으로 인해 이 기능을 소프트웨어로 에뮬레이션해야 했습니다. 결과적으로 ONTAP Select 클러스터 내에서 HA 인터커넥트 기능(기존에는 하드웨어로 제공)이 이더넷을 전송 메커니즘으로 사용하여 운영 체제에 내장되었습니다.

각 ONTAP Select 노드에는 HA 인터커넥트 포트(e0f)가 구성되어 있습니다. 이 포트는 HA 인터커넥트 네트워크 인터페이스를 호스팅하며, 이 인터페이스는 두 가지 주요 기능을 담당합니다.

* HA 쌍 간 NVRAM 내용 미러링
* HA 쌍 간에 HA 상태 정보 및 네트워크 하트비트 메시지 송수신


HA 인터커넥트 트래픽은 이더넷 패킷 내에 RDMA(원격 직접 메모리 액세스) 프레임을 계층화하여 단일 네트워크 인터페이스를 통해 이 네트워크 포트로 흐릅니다.


NOTE: RSM 포트(e0e)와 마찬가지로 물리적 포트와 호스팅된 네트워크 인터페이스는 ONTAP CLI나 System Manager에서 사용자에게 표시되지 않습니다. 따라서 이 인터페이스의 IP 주소를 수정하거나 포트 상태를 변경할 수 없습니다. 이 네트워크 포트는 점보 프레임(7500~9000 MTU)을 사용해야 합니다.
